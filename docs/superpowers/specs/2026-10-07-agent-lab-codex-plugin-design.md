# Agent Lab：Codex 插件版设计

日期：2026-10-07。

状态：插件路线已确认；用户要求继续规格与计划。本版完成实施前细化，作为 P1 的产品规格。运行代码与插件安装尚未开始。

## 1. 已确认的方向

用户在比较独立客户端与 Codex 插件后选择“先做插件”，并明确要求使用 Superpowers。沿用此前讨论的完整平台目标：自然语言提出研究问题，Codex 制定与执行实验，多 API、多技术接入，保存日志和证据，提供可检查的实验看台。

首个宿主是用户现有 Codex 客户端。插件负责研究工作流与工具接入；本地实验服务负责配置、调度、证据和计算；看台在浏览器中显示，并可在 Codex 的侧边打开。CLI 与 MCP 调用相同的服务操作。以后加入独立客户端时复用这些边界。

此前总体方案保留为长期产品蓝图；本文覆盖插件路线和插件首个研究闭环。内置主持 Agent、Codex SDK/app-server 客户端、团队协作和远程 worker 放在后续独立子项目中。首版采用本地存储，替代总体草案中的 PostgreSQL 首版建议；数据库语义保持可迁移。

## 2. 用户得到什么

在 Codex 中提出：“比较滑动窗口和摘要上下文，哪种更容易引用过期事实？”插件工作流将研究问题写入平台，建立可复核的实验草案，选择 API 连接、策略、场景和判分，预览样本数量与资源限制，冻结并提交实验。

运行提交后立即得到实验 ID 和看台地址。Codex 可以继续讨论，也可以结束会话；已提交的实验由服务继续管理。用户从看台检查进度、失败、成本与证据，在 Codex 中引用案例 ID 继续分析，并派生下一轮实验。

用户也能直接用 CLI 完成同样操作。安装入口和凭据配置有明确诊断；没有可用 API 凭据时，可以通过带显式标识的确定性测试后端验收安装与运行机制，其输出不能被当成模型研究结论。

## 3. 分解与交付边界

平台分成三个依赖相连的子项目，每个子项目单独产生实现计划和验收。这个分解保留大平台的目标，同时使首个交付可以实际使用。

| 子项目 | 交付内容 | 边界 |
| --- | --- | --- |
| P1：插件研究闭环 | 可安装插件、Skill、CLI/MCP、实验服务、白盒运行器、多 API、基础策略、证据与默认看台 | 本文详细规定；先形成实现计划 |
| P2：外部技术实验 | MCP 工具实验套件、Mem0 适配器、其他库/服务接入、完整 Harness 适配与契约验证 | 复用 P1 注册表和证据格式；按实际产品文档单独设计 |
| P3：动态研究看台 | 组件目录、可持久化 ViewSpec、按问题调整分析视图、扩展视图隔离 | 复用 P1 的指标定义与样本引用；不依赖更换宿主 |

P1 按依赖进一步拆成四个可验收交付：A 实验与证据内核、B 多 API 与策略运行、C Codex 插件与工具接口、D 指标与默认看台。[交付路线图](../plans/2026-10-07-agent-lab-delivery-roadmap.md)规定全部 P1 工作及验收映射；[A 的规格](./2026-10-07-agent-lab-core-design.md)与[详细实施计划](../plans/2026-10-07-agent-lab-core.md)规定首个可独立执行的子项目。A 的离线结果用于验证实验基础设施；B 的真实模型实验和 C/D 的安装、看台验收全部通过后，才称 P1 插件研究闭环完成。

P1 必须有真实 API 运行能力、可重开的结果和端到端证据。它不是只提供说明文本的 Skill，也不是只显示演示数字的界面。P2/P3 的尚未支持能力在扩展库中清楚标记，不能伪装成可用插件。

## 4. P1 结构与技术选择

```text
Codex 对话
  ├─ Agent Lab Skill：研究流程、工具选择、结果引用
  ├─ MCP 工具：结构化调用
  └─ CLI：适配器开发、批处理、诊断
             ↓
       本地实验服务
         ├─ 规格与注册表
         ├─ 调度器与独立 worker
         ├─ 判分与指标查询
         └─ 证据存储
             ↓
       Web 看台、JSON/JSONL 导出
```

实现代码位于独立的 `shiyanpingtai` 仓库，远程地址为 `https://github.com/wuwuyuaa/shiyanpingtai.git`。Python 包使用 `src/agentlab/`，插件使用 `plugins/agent-lab/`，看台使用 `web/`；文件职责由交付路线图和子项目计划规定。实验数据位于各研究工作区的 `.agentlab/`，与仓库、插件缓存和开发 worktree 分开管理。

建议 Python 负责服务、CLI、MCP 和适配器，使用有类型的规格校验。服务采用 FastAPI，核心 CLI 使用标准库 argparse，MCP 使用固定版本的官方协议实现库。看台采用 React/TypeScript。首版 SQLite WAL 保存元数据和持久队列，文件存储保存大产物；只有应用服务负责状态变更，客户端和 worker 通过定义的接口提交结果。

单台机器支持多个连接入口、有限并发实验 worker。不引入分布式调度。依赖版本在实现时锁定并验证，本文不把尚未查证的包版本当作已确定事实。

每个工作区有显式 ID 与数据目录；所有 CLI 和 MCP 调用解析到同一个工作区，响应包含其 ID。默认使用项目的 `.agentlab/` 数据目录，可通过专用配置覆盖。运行数据与密钥文件不纳入 Git；测试夹具与场景定义可以纳入 Git。

跨子项目的规格、错误、事件、证据与接口约定以[公共契约](./2026-10-07-agent-lab-contracts.md)为准。冻结规格与运行状态是不同对象：A 可保存不可变规格，B 提交运行时才生成 queued 运行。A 的 CLI 在本进程调用应用服务；B/C 的运行与工具入口通过本地服务接口调用同一应用语义，客户端从不直接修改 SQL 表。

### 4.1 插件包装

优先使用官方当前的根目录 `plugin.json`、`skills/` 与 `mcp.json` 结构。针对实际安装版本确有需要时输出兼容清单，并验证两种包装的组件映射一致。使用仓库/本地 marketplace 分发，先在本机验证，不把发布到公共目录作为首版前置条件。

插件内置 stdio MCP 桥接进程，它连接已经启动的本地服务。桥接进程退出不终止服务或实验 worker。插件资源不得依赖被缓存复制后失效的开发目录相对路径；安装诊断检查运行时、包安装、工作区、服务状态、插件清单和工具发现。

首版研究执行不依赖 Hooks。Hooks 可在后续独立增加，用于补充宿主观测；实验的必要证据由运行器生成，不能依赖会话结束时导出的宿主日志。

### 4.2 服务生命周期

`agentlab serve` 以明确的工作区运行服务与调度器；`agentlab status` 查询服务和 worker；看台关闭和 MCP 退出都不取消服务中的任务。Skill 首次使用检查服务状态，缺失时指导或调用有明确进程归属的启动操作，等待健康检查成功后再提交。

服务监听本机回环地址。连接信息存放在工作区的受限运行文件中，响应和看台 URL 不包含凭据。MCP/CLI 使用工作区连接凭据；看台的写操作校验本地会话凭据和来源。端口探测或同一端口有响应不足以证明连接的是正确工作区服务。

## 5. 实验流程与操作契约

下列名称是本平台拟议接口，不是已有 Codex 命令。

| 操作 | 输入 | 输出与规则 |
| --- | --- | --- |
| research.create / update / inspect | 问题、工作区、决策和证据引用 | 研究 ID、摘要、关联实验；不复制全部宿主对话 |
| connections.configure / list / check | 连接配置、凭据引用、所需能力 | 配置版本、可用性与能力结果；不返回密钥 |
| extensions.list / inspect | 类型、版本、能力条件 | 已支持的实现与限制 |
| experiment.create / revise | 研究 ID、完整草案 | 草案 ID/版本；修改生成新草案版本 |
| experiment.validate | 指定草案版本 | 组合兼容性、运行数、上限、可估计费用、错误 |
| experiment.start | 已校验草案版本、幂等键 | 冻结版本与实验 ID；同键同内容重复提交返回原结果 |
| experiment.inspect / cancel | 实验 ID | 状态、汇总、取消请求结果 |
| experiment.pause / resume | 实验 ID | 修改 scheduling_paused；在途任务继续，恢复后领取新任务 |
| runs.list / inspect | 实验与运行 ID、分页、证据种类 | 场景、变体、尝试、事件及产物引用 |
| runs.retry / scores.regrade | 运行或实验 ID、目标判分版本、幂等键 | 新 Attempt 或新 ScoreSet；保留历史，不隐式选择最高分 |
| compare / metrics.query | 冻结实验、指标、筛选和聚合 | 服务计算的值、口径、分母、样本引用 |
| evidence.read / export | 证据 ID、大小限制 | 内容或工作区内产物引用；拒绝任意文件读取 |
| dashboard.open | 研究/实验/案例 ID | 可打开的本地看台地址与当前服务状态 |

CLI 的机器模式输出结构化 JSON，事件模式输出带游标的 JSONL；诊断写 stderr。MCP 使用类型明确的工具参数与结果，耗时运行返回 ID，不能把一次工具调用保持到整个矩阵结束。MCP 与 CLI 的校验、错误码、幂等和权限语义相同。

费用和权限沿用用户已授权的实验范围。既有范围内的重复运行不反复索取同一批准；超出范围的资源、外部效果或预算变更由新实验规格明确呈现。API 凭据选择与真实调用前的配置按对应凭据工作流处理，不在设计阶段收集密钥。

Skill 应让 Codex 按“问题与假设 → 草案 → 校验 → 冻结提交 → 查进度 → 比较 → 引用证据”推进。服务负责执行约束，不能仅依靠 Skill 文本约束状态或预算。

## 6. P1 的研究能力

### 6.1 多 API

P1 提供 OpenAI 原生接口、Anthropic 原生接口和明确标识的 OpenAI 兼容接口三类模型连接。原生参数和原始响应保留在各自适配器中；连接检查验证当前实验真正需要的能力。兼容端点不推定具备原生端点的全部能力。模型名可配置，不写死为设计日期的某个型号。

连接引用环境变量或用户配置的安全凭据来源，数据库只存引用。出站请求的鉴权字段与凭据不写入日志。请求内容、响应、实际模型标识、可获得的用量、计时、错误与重试记录为证据。未知用量与价格保持未知。

### 6.2 基础策略与场景

P1 提供三项基线策略：

1. 滑动窗口：保留预算内的最近历史，记录排除内容和实际请求。
2. 滚动摘要：使用显式配置的摘要模型逐段生成摘要，保存输入来源、摘要版本与额外调用成本。
3. 带来源和时间的结构化记忆：显式配置提取模型保存事实、更新时间、来源及替代关系，保存候选、检索结果和注入内容。

第三项的时间更新规则与检索方法是该策略自己的定义，不能被当成所有记忆系统的共同接口。所有模型辅助的提取、摘要和检索费用纳入对应运行。

首个场景集覆盖事实更新、长间隔信息、干扰信息与证据不足时的回答。每个场景有版本、按时间开放的历史、提问和独立答案规则；判分器能检查具体任务结果及引用来源。标准比较按相同场景配对；策略对同一问题无效时记失败，不从分母删除。

支持同模型比较策略、同策略比较模型及指定维度的交叉实验。重复编号、场景、逻辑种子与执行顺序保留，独立运行的记忆隔离。逻辑种子用于数据与环境，不承诺托管模型输出完全确定。

### 6.3 扩展边界

P1 定义版本化的 Model、Memory、Context、Tool、Harness、Scenario、Evaluator 分类接口和能力描述。实现可以是包、服务或子进程；不得仅通过加载任意文件就自动获得可信和可用状态。

契约包含配置校验、准备、调用、证据导出、可用的重置或隔离方式与清理。某类型不支持状态隔离时，校验器阻止依赖独立重复的实验。未知技术仍需适配，不把“协议连接成功”当作业务语义已验证。

P1 内置基线及确定性测试适配器；P2 以真实 MCP 服务和 Mem0 作为首批外部技术接入验收。它们在 P2 完成前显示为后续支持，不出现在可执行矩阵中。

## 7. 状态、证据与恢复

核心对象：Research、ExperimentDraft、FrozenExperiment、Variant、ScenarioVersion、Run、Attempt、Event、Artifact、ScoreSet、MetricDefinition、Connection 和 ExtensionVersion。

冻结的实验保存配置哈希、场景/代码/提示/适配器版本、模型选择、参数、资源限制和判分定义。启动、worker 抢占和运行状态提交使用事务与幂等键。相同键提交不同内容报冲突，不静默复用。

实验状态：queued、running、cancel_requested、completed、completed_with_failures、cancelled、interrupted。每个 Run 分别记录 queued、running、succeeded、failed、cancelled、interrupted；Attempt 记录一次执行或恢复尝试。终态不能因晚到 worker 消息被覆盖。

调度暂停作为 scheduling_paused 属性记录，不把仍有在途运行的实验伪装成已经停止。worker 结果必须绑定当前 Attempt 和有效租约代际；过期 worker 的回报保存为迟到证据但不得修改当前状态或判分选择。

事件带研究/实验/运行/尝试 ID、顺序、时间、类型、父事件和产物引用。保存记忆写入、候选与检索、上下文构建、实际模型请求与响应、额外模型调用、工具调用、判分与资源事件。大内容以哈希寻址的产物保存，原证据不被后续摘要或重新判分覆盖。

调度器持久化队列与 worker 租约。服务重启后未开始的运行继续排队；过期在途运行标为 interrupted。P1 重新执行从场景起点开始，生成新 Attempt，旧证据保留并显式说明可能产生额外模型费用；不承诺恢复供应商未知完成状态。未来有外部副作用的工具任务需要专门恢复协议，不能沿用白盒无外部动作的重跑规则。

暂停调度停止领取新任务，取消同时要求在途 worker 终止。取消成功后仍保留已发生的响应和费用。预算按实验任务阶段记录调用数、token、耗时、并发及费用；具有价格和可估算用量时预留在途额度。调用数和调度时间上限由服务执行，输出规模由供应商支持的参数约束；token 上限仅在能可靠计量或保守预留时声明为硬约束，否则显示为估计并允许实验要求阻止该组合。价格未知时不能声称严格满足货币上限。传输重试保留次数和原因，不作为新的独立样本。宿主 Codex 的用量只从公开可获得的信息记录，缺失时保持未知，不与被测模型用量混合。

## 8. 看台与分析

P1 默认看台包含研究/实验列表、冻结方案与矩阵、运行进度、指标比较和逐案例证据。页面顶部常驻实验版本、状态、数据截止点、失败/缺失数与预算。宿主对话继续留在 Codex，看台保存平台研究摘要和引用。

基础指标包括任务正确率、过期事实错误率、来源引用准确度、实际可获得的输入/输出用量、耗时、费用和运行失败率。每个指标保存定义、单位、分母、缺失处理、方向和版本；没有来源的指标不展示为实测数据。

比较同时展示全体计划样本的完成/失败分布，以及明示条件的已完成配对结果。按场景聚合独立重复，用场景为单位估计配对差值和不确定性；样本不足时显示数据限制，不生成虚假的显著性结论。运行中结果标为阶段数据。

点击差异可查看两项配置在同一场景上的实际上下文、记忆状态、响应、判分依据和错误。看台提供“复制案例引用”，用户粘贴回 Codex 后 Skill 查询该引用；首版不依赖尚未验证的自动注入宿主会话接口。

看台通过持久事件游标和服务查询刷新，重开后保持有效；导出保存规格、原事件、产物、评分与指标定义。P3 在这些结果上加入动态 ViewSpec，不让 Agent 自行编造图表数值。

## 9. 验证与验收

| 验收 | 必须观察到的证据 |
| --- | --- |
| 可安装且可发现 | 插件清单通过本机验证；已安装副本中的 Skill 与 MCP 工具能在新会话发现；不能仅用开发目录测试代替 |
| 入口一致 | 同一规格通过 CLI/MCP 校验得到相同展开矩阵；重复提交不新增实验 |
| 真实研究闭环 | 至少一项实际配置的 API 跑完两种策略的配对场景；配置缺失时明确报告，测试后端结果有测试标识 |
| 多连接可扩展 | 原生与兼容适配器协议测试通过；不支持的参数/能力在启动前报错；已验证和仅协议测试的范围分开 |
| 实验隔离 | 多重复、并行运行和事实更新场景不会串记忆，裁判答案不进入请求 |
| 证据完整 | 从某个错误分数能追到运行、请求、记忆来源、响应和判分版本 |
| 生命周期正确 | 关闭看台或 MCP 后实验继续；服务重启没有重复提交；中断和重跑保留 Attempt；取消不抹去历史费用 |
| 指标正确 | 在固定夹具上核对分母、失败、缺失和配对差值；重新判分不会覆盖旧 ScoreSet |
| 看台可用 | 实测数据可刷新、筛选、进入案例、复制引用并导出；人工检查页面和关键交互 |

实现采用 Superpowers 的实现计划、适当的测试驱动、调试与完成前验证流程。必要测试集中在状态、隔离、接口一致性、评测口径和真实集成边界；不为每个低影响展示调整机械增加测试。
