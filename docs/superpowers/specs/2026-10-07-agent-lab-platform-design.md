**Agent Lab：可插拔 Agent 技术实验平台与动态研究看台**

日期：2026-10-07。状态：第一版设计提案，供用户结合交互稿评审。本文记录拟议设计，不表示功能已经实现或用户已批准全部技术取舍。

2026-10-07 路线更新：用户选择“先做插件”，并要求使用 Superpowers。首个交付采用现有 Codex 作为研究宿主，插件连接本地实验服务和独立看台；详细边界见 [Codex 插件版设计](./2026-10-07-agent-lab-codex-plugin-design.md)。本文保留长期蓝图；内嵌主持者、独立研究客户端、远程协作，以及首版 PostgreSQL 的建议不作为插件首个闭环的前置要求。

**产品目标是让用户接入、组合和评测各种 Agent 技术，并持续讨论、运行实验和复核证据。** 研究对象覆盖模型 API、MCP 服务、记忆系统、新上下文机制和完整 Agent/harness。用户选择 Codex 或平台内置 Agent 主持；主持者制定假设、构造实验和分析失败；平台负责版本、运行、数据、判分与证据。图形界面与 CLI 操作同一组研究和实验。

用户已明确：按完整平台设计；支持多个 API；同时支持图形入口与 CLI；支持 Codex 和内置 Agent 主持；本轮需要方案与生图交互稿。交互稿使用演示数据。

后续补充目标：可以即插即用地实验市面上的 MCP、Mem0 等系统，以及自定义的新记忆和上下文方法；提供实验指标看台。本文增加扩展体系与动态看台建议。新增要求是用户已表达的目标；下面的适配器机制、协议选型和看台分层仍是待评审设计。现有三张图片是以记忆实验为例的第一轮交互稿，尚未展示新增扩展库与动态看台。

**产品形态选择：推荐本地服务加 Web 工作台，CLI 连接同一服务。**

| 方案 | 优点 | 代价 | 判断 |
| --- | --- | --- | --- |
| 本地服务 + Web 工作台 + CLI | 本地启动，适合接 Codex、文件与实验环境；UI 与 CLI 共享数据；可扩展远程 worker | 需要服务生命周期与本地连接管理 | 推荐作为平台基础 |
| 原生桌面客户端 + CLI | 启动、系统通知、钥匙串和窗口体验更完整 | 分发、更新和跨系统成本较高 | 在共享服务成熟后封装桌面壳 |
| 云端 Web 平台 + CLI | 远程任务和团队协作方便 | 本地代码、凭据、计算环境连接更复杂 | 部署演进方向 |

第一版图形产品以桌面尺寸 Web 工作台为准；核心边界允许后续放入桌面壳。客户端关闭不停止已提交到服务的任务。CLI 不直接修改数据表或绕开调度器。

**即插即用需要共同的生命周期，以及按能力分类的适配接口。** 平台提供扩展库，登记名称、类型、版本、运行方式、配置结构、认证引用、能力声明、事件、产物与自检。每种扩展实现适合自身的接口，不把任意产品压成同一个调用签名。

| 扩展类型 | 示例 | 插入位置 | 专门检查 |
| --- | --- | --- | --- |
| 模型连接 | 原生 API、自定义兼容端点、本地推理服务 | 模型调用 | 能力、参数语义、用量可见性 |
| 工具连接 | MCP server、HTTP 工具、命令行工具 | Agent 与环境交互 | 发现、参数、业务结果、延迟和失败 |
| 记忆 | Mem0、文件记忆、时间事实库、新论文实现 | 写入与取回历史信息 | 更新、检索、隔离、时效、状态清理 |
| 上下文策略 | 截断、摘要、检索组装、动态加载 | 模型请求前的工作集构造 | 信息保留、输入规模、构造成本 |
| Agent / Harness | 自建循环、Codex、第三方运行系统 | 完整任务执行 | 行动成功、恢复、预算及可观测范围 |
| 环境与场景集 | 订单沙箱、城邦模拟、固定日志 | 提供任务、观察与反馈 | 初始状态、时间可见性和重置 |
| 判分器 | 程序断言、固定模型裁判、人工规则 | 运行结束或指定检查点 | 定义、独立性、版本与判分证据 |
| 可视化扩展 | 记忆图、上下文差异、工具链路视图 | 研究看台 | 数据绑定、只读能力和来源导航 |

MCP 是接入工具和资源的协议；通过 MCP 暴露的记忆服务，还需要映射到记忆评测的语义接口。发现工具不代表已经知道怎样初始化、隔离、清理和正确评价某个服务。

**接入可以有三种路径。** 已有适配器通过配置完成注册；新的标准连接通过地址或启动命令发现能力，完成自检后使用；未知 Git 仓库、包或服务可由 Codex 阅读文档并生成适配器，在隔离环境通过契约测试后注册。第三种路径是建议能力，接入结果须明确显示已验证与未支持的范围，不能承诺任何仓库都能无适配运行。

适配器最少描述 prepare、能力发现、执行、观测导出、状态重置、cleanup。实际命名按 SDK 设计；不是所有扩展都具备全部能力。不能可靠重置或隔离的外部服务，应标为限制条件，并阻止要求独立状态的实验协议。每个运行绑定扩展版本和依赖快照。

适配器验证包括两层：接口与生命周期是否工作，以及业务语义是否符合该评测套件。插件可以推荐指标和场景；标准比较使用平台独立管理的套件与判分版本。插件自己的评分标为自报告，不能替代独立验收。

**比较单位是同一研究问题下的一组完整配置。** 可以比较同模型加不同记忆，或同工具后端的直接调用与 MCP 接入；只有控制住其他差异，才能把结果归因到某个组件。不同任务、环境或判分定义的分数不混为总榜。

一个实验可以组合模型连接、工具集、记忆、上下文策略、harness、场景集与判分器。扩展的能力声明用于检查组合能否运行；执行层仍保留供应商原始语义和未知状态。矩阵按指定维度展开，避免默认对所有组件做无意义的笛卡尔积。

**研究主持者、被测对象和裁判是三个独立角色。**

| 角色 | 职责 | 配置 |
| --- | --- | --- |
| 研究主持者 | 讨论问题、生成实验方案、调用平台工具、解释结果、提出下一轮实验 | Codex 连接或内置 Agent；可单独选择模型与预算 |
| 被测对象 | 在指定模型/API、记忆、上下文与工具条件下完成场景 | 模型连接、策略组合、参数、环境版本 |
| 判分器 | 根据冻结的标准评价任务结果 | 程序断言、固定模型裁判、人工标注；分别记录 |

主持者有自己的研究记录，与被测 Agent 的记忆存储隔离。裁判答案不进入被测上下文。主持者可以分析开发集失败；封存测试集的答案与细粒度反馈按实验协议开放，防止循环调优污染留出评测。

**一个完整使用过程应当是：**

1. 用户新建研究，输入“比较普通摘要和结构化记忆，哪个更少使用过期信息”。
2. 选择研究主持者、研究预算与可用实验 API 连接。
3. 主持者生成结构化实验方案：假设、变量、对照、场景、重复次数、判分与资源上限。
4. 工作台显示可编辑的方案卡。用户可以修改矩阵，也可以通过 CLI 提交同样的规格。
5. 方案通过能力兼容和预算检查后，冻结成一个实验版本并启动。研究中已经授权的范围可连续执行；预算扩大或实验边界改变时呈现明确变更。
6. 运行时看到完成数量、失败、费用和场景证据；支持暂停排队、取消、重试失败运行和断线重连。
7. 结果按场景配对比较。点击差异进入具体运行，查看记忆写入、检索、上下文和实际动作。
8. 用户与主持者讨论结果；下一轮以新版本或派生实验保存，不覆盖旧配置和结果。

**图形工作台围绕研究对象组织。** 左侧是研究、实验、扩展库、场景集和连接管理；研究内部提供对话、实验方案、看台与证据。扩展库可按模型、MCP、记忆、上下文、harness 和可视化筛选。对话内容可以引用方案、运行、看台和证据，并把这些引用保存为稳定对象链接。

研究页上方显示主持者与连接状态。实验 API 和裁判设置出现在实验方案里，避免把“换主持模型”误解为“换实验模型”。右侧产物区有方案、运行、比较、证据四个主要标签。

比较页优先展示每个方法的结果与失败分布。进入证据页后，左侧是可过滤的场景列表，中间是两种方法在相同场景下的上下文或记忆对照，右侧是判分依据。可进一步展开原始请求与响应、工具调用和文件产物。研究对话保持可访问，便于直接追问选中的失败。

**看台采用固定框架、动态组件编排和隔离扩展三层结构。**

| 方案 | 优点 | 代价 | 建议 |
| --- | --- | --- | --- |
| 固定看板模板 | 一致、容易比较、可直接验收 | 每类新结果需要补视图 | 用作总览和默认模板 |
| Agent 生成结构化视图说明，客户端用已注册组件渲染 | 可以随研究问题调整，又保留可验证的数据绑定 | 要维护组件目录、数据契约与视图校验 | 主要的动态展示方式 |
| Agent 或插件提供自定义前端产物 | 适合全新的交互和特殊图形 | 有渲染、依赖、隔离和语义审查成本 | 作为独立扩展面板 |

固定框架始终展示实验身份、版本、进度、预算、失败与缺失、当前筛选和原始证据入口。Agent 不能通过动态布局隐藏这些基础信息。默认组件包括指标表、配对差值、成本与效果散点图、分布图、时间线、失败样本、上下文差异、记忆变化和工具轨迹。

Agent 根据研究目标选择组件、指标、分组、筛选与说明，生成拟议的 ViewSpec。它引用平台的 MetricDefinition、数据查询和证据 ID；客户端检验组件、字段类型和权限后渲染。ViewSpec 是平台内部拟议契约，不声称等同于任何外部协议。

指标由执行与分析服务计算。每个定义保存版本、单位、统计粒度、分母、缺失处理、方向、聚合函数和来源。Agent 可以提出新分析；需要计算新指标时，注册可检查的计算定义或分析产物，并由服务执行。图表不能把对话中的无来源数值直接作为实测指标。

每个面板能打开指标定义、查询范围和底层样本。运行期看台显示数据截止点与未完成数量；筛选后的分析标为探索性切片，不能覆盖冻结的主要评测口径。视图布局、查询和结果快照可以保存，图形工作台与 CLI 都能重新打开同一版本。Agent 结束后，已有看台仍由数据事件更新与客户端渲染。

特殊前端产物或 MCP App 在隔离面板渲染，默认只获得指定实验的只读数据与产物访问。操作意图经平台接口校验后执行；面板不能直接改写运行、评分或数据库。能够渲染自定义页面不代表它的统计口径已获验证。

**现有界面协议可以作为适配层。** A2UI 的组件目录允许 Agent 输出声明式界面，再由客户端渲染已注册组件；适合借鉴动态看台的描述方式。AG-UI 负责 Agent 与前端之间的事件和交互；平台自己的持久实验事件与数据模型仍须独立定义。MCP Apps 允许工具关联 UI 资源，并在宿主中渲染交互界面；适合嵌入第三方工具视图，也可以让平台的看台在支持该扩展的宿主中展示。三者职责不同，不把采用全部协议作为首版前置条件。[A2UI Catalog](https://a2ui.org/guides/defining-your-own-catalog/)、[AG-UI](https://docs.ag-ui.com/introduction)、[MCP Apps](https://apps.extensions.modelcontextprotocol.io/api/documents/overview.html)

例如用户提出“只看历史超过三万 token 时，Mem0 与结构化摘要的成本和成功率”，主持者申请一个明确的实验切片；分析服务返回相应指标与样本引用；看台新增散点图、样本量与失败表。点击某个失败点进入原始证据，继续对话时携带该案例引用。

API 连接页保存供应商、协议、端点、模型目录、认证引用、能力检测结果、速率限制和价格版本。凭据由服务安全存储，界面和日志显示引用及掩码。连接检查报告鉴权、模型可访问性和所需能力；模型列表出现某项不代表账号必然可调用。

实验矩阵编辑器允许选择多个模型连接和多种策略，但分别提供“同模型比较方法”“同方法比较模型”和“完整交叉”模式。预览有效单元、不可兼容组合、样本量和费用估计。token 预算可用于同模型方法对照；跨模型比较还需报告相同语料、调用约束及实际费用，不能把不同 tokenizer 的相同数字视为完全相同的信息量。

**CLI 是公开的机器接口，也是高级用户入口。** 以下命令为本平台拟议语法，不是已有命令：

```text
agentlab research create --question "哪种记忆更少引用过期事实？" --json
agentlab experiment validate experiment.yaml --json
agentlab experiment run experiment.yaml --json
agentlab run watch RUN_ID --format jsonl
agentlab run inspect RUN_ID --include context,memory,tools --json
agentlab compare EXPERIMENT_A EXPERIMENT_B --json
agentlab research handoff RESEARCH_ID --to builtin --json
```

机器模式 stdout 只输出结构化结果，stderr 输出诊断；使用稳定错误码、对象 ID、分页与事件游标。提交具有幂等请求 ID。长任务返回任务 ID，watch 可以断线续读。所有变更命令与 UI 使用同一服务接口和权限语义。

**Codex 既能在外部操纵 CLI，也能作为工作台中的主持者。** 外部模式由用户自己的 Codex 会话调用平台 CLI，研究页显示其活动和结果；嵌入模式通过 Codex 的集成接口把对话、事件和交互呈现在工作台。官方当前建议程序化任务使用 SDK，丰富持久交互使用 app-server。本设计采用适配器封装，不把 Codex 的内部会话格式作为平台研究记录的唯一格式。[Codex 平台说明](https://developers.openai.com/blog/codex-as-a-platform)、[App Server](https://learn.chatgpt.com/docs/app-server)、[SDK](https://learn.chatgpt.com/docs/codex-sdk)

平台内置主持者使用自己的执行循环，通过同一组研究工具制定和运行实验。两种主持方式共享能力接口，但不承诺不同 Agent 的隐藏状态、系统指令或推理过程能够完整转换。

切换主持者时，服务暂停旧主持者发起新变更，在可恢复边界生成交接记录：研究问题、已确认决策、当前实验、未决事项、证据引用和剩余预算。已有实验归调度器继续管理；新主持者通过平台状态恢复工作。单个研究只允许一个活动写入主持者，使用租约与代际标识拒绝旧连接继续提交；只读分析者可以并存。

**实验平台必须区分比较方法与比较整个产品。**

- 白盒实验：平台控制模型请求、记忆与上下文，可检验具体方法。
- 黑盒实验：把 Codex 或其他封装 Agent 当作被测对象，只记录公开可获得的信息；未暴露的上下文与成本标记为未知。
- 主持 Codex 研究的模式独立于“评测 Codex 本身”。两者可以同时存在，但必须具有独立会话、预算和数据范围。

**系统由以下边界清晰的子系统组成。**

| 子系统 | 负责什么 | 主要输入输出 |
| --- | --- | --- |
| 研究服务 | 研究问题、讨论、决策、主持者交接 | Research、消息、引用、交接记录 |
| 实验规格与注册表 | 版本化实验、策略、数据集、连接能力 | ExperimentSpec、版本与内容哈希 |
| 调度与运行 | 排队、并发、预算、恢复、隔离 | Run、Attempt、运行事件 |
| 模型连接层 | 原生协议适配、能力检查、费用与请求记录 | 规范化调用与原始供应商记录 |
| 策略运行层 | 记忆写入/读取、上下文构造、工具与环境 | 策略实例、观察、动作、状态 |
| 证据存储 | 事件索引、上下文快照、记忆变化、产物 | 可寻址且版本固定的证据 |
| 判分与分析 | 终态断言、模型裁判、人工标注、配对统计 | ScoreSet、比较结果、报告 |
| 扩展接入与验证 | MCP、库、服务和命令行适配，能力与生命周期自检 | ExtensionManifest、适配器版本、兼容结果 |
| 动态看台 | 注册组件、验证视图、绑定分析结果、隔离扩展面板 | ViewSpec、MetricDefinition、查询与看台快照 |
| 客户端接口 | UI、CLI、事件流和 Agent 工具 | 同一套服务契约 |

建议技术组合为 React/TypeScript 工作台、Python 实验服务与插件生态、PostgreSQL 元数据与队列、文件或兼容对象存储保存大产物。CLI 使用 Python 包装同一 API。初始 worker 可本地运行，服务契约支持远程 worker。是否采用桌面壳、分布式队列和更多语言适配，在对应子系统规格中根据实际部署需要决定；本文的核心职责与数据语义不依赖某个框架。

**核心对象需要在首版统一。** Research 是长期研究；Experiment 是冻结的一次实验设计；Variant 是矩阵中的一项配置；Scenario 是版本化场景；Run 是某配置、场景和重复编号的执行；Attempt 记录恢复或重试；Artifact 保存证据；ScoreSet 保存特定裁判版本的判分；ExtensionManifest 描述扩展；MetricDefinition 定义指标口径；ViewSpec 定义看台；Report 引用比较与证据。重新判分新增 ScoreSet，不更改原始运行。

每个 Run 保存数据集与策略版本、代码快照、提示版本、模型标识及可获得的供应商指纹、参数、可见性范围、预算、环境种子和实际费用。用户选择的逻辑模型名与供应商实际返回的标识分别保存。供应商更新无法完全冻结时标明复现边界。

**日志既要保存可读结果，也要能追踪信息在哪一步变化。** 事件包含事件 ID、研究/实验/运行/尝试 ID、顺序、时间、父级事件、类型与产物引用。主要事件覆盖 memory.write、memory.retrieve、context.build、model.request/response、tool.call/result、checkpoint、grade 和 budget。名称是拟议内部事件，不直接暴露为普通用户操作。

大原文保存为产物，索引包含来源和内容哈希；记录“确实发给模型的输入”及供应商公开输出，不伪造不可获得的隐藏推理。上下文比较能追踪候选记忆、选入内容、截断和摘要来源。摘要与原始事件保持关联，不能覆盖原证据。

**实验正确性有以下基础规则。**

1. 同一次已冻结实验不能静默修改模型、策略、数据集或判分标准。
2. 每次独立重复运行隔离记忆和环境；跨任务学习范围在实验规格中显式声明。
3. 场景只暴露截至当前时间允许看到的信息，未来事件与裁判答案隔离。
4. 模型连接不能静默丢弃参数或用另一语义的参数替代；不支持的组合在启动前标出。
5. 传输重试与新的独立采样分开记录，原始失败保留，不能只挑成功尝试计分。
6. 费用同时记录主持、建忆、摘要、模型、工具与裁判。未知价格标未知，费用上限可能受在途请求影响，另设调用、token 和时间限制。
7. 实验中途结果标为阶段数据；最终比较显示样本数、缺失与失败、逐场景差值和估计不确定性。

**失败与恢复要覆盖服务、供应商与实验环境。** 服务重启后恢复队列和最后持久化状态；worker 丢失标为中断，查明是否发生外部效果再决定恢复或重新运行。429、暂时网络错误与永久请求错误采用不同策略，重试受次数和预算限制。取消先停止新调度，再处理在途调用；取消不承诺撤销已经完成的外部效果。

具有副作用的模拟工具使用稳定操作 ID 和工具端去重。研究阶段优先隔离环境，真实外部动作按实验授权单独配置。导入日志或未知记忆作为数据处理，其内容不能提升为平台指令。插件允许范围、依赖版本和执行环境纳入可复核配置。

**首个完整产品版本应包含一条真正可用的研究闭环。** 两种入口、多 API 连接、两种主持方式、矩阵运行、恢复与预算、逐步证据、比较和报告都在产品范围中。按子系统分段实现，每段复用同一对象与接口，而不是同时展开所有界面。

| 交付段 | 主要成果 | 验收 |
| --- | --- | --- |
| A：实验与证据核心 | 规格、场景、连接、单机 worker、事件、CLI | 同一实验可提交、断线续查、取出完整证据 |
| B：研究工作台 | 对话、方案卡、矩阵、进度、比较、证据 | 从一个研究问题走到可复核结论 |
| C：主持者适配 | 外部 Codex、嵌入 Codex、内置 Agent、交接 | 切换后无重复提交，当前实验继续可见 |
| D：研究能力扩展 | 数据集划分、策略插件、重新判分、回归与报告 | 对照试验可重复，变更有来源与版本 |
| D2：扩展生态与动态看台 | 分类适配器、自检、组件目录、动态视图、隔离面板 | 接入新技术后可建立有效对照，图表可追溯与重开 |
| E：部署与协作 | 远程 worker、桌面包装、协作权限 | 多入口同时查看，写入和凭据边界清晰 |

**验收应同时覆盖产品交互和实验语义。** UI 和 CLI 提交同一规格得到相同配置；能力不支持时明确阻止该组合；断线不导致重复实验；主持者交接拒绝旧写入者；记忆在不同重复之间隔离；裁判结果可以回指原始证据；版本变化不会覆盖历史；费用缺失保持未知；失败案例能从比较页直接追踪到上下文与动作。
